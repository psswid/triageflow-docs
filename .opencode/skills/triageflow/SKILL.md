# TriageFlow Skill

> Domain-specific conventions for TriageFlow: AI-assisted patient triage showcase. Load this skill before working on any medical/AI domain logic, data modeling, or triage pipeline code.

## When to Load This Skill

Load before:
- Creating or modifying triage pipeline logic
- Working with AI integration (symfony/ai)
- Designing medical domain models
- Building patient intake UI
- Generating synthetic medical data
- Writing system prompts for AI triage analysis

## Medical Domain Conventions

### Clinical Terminology

| Term | Type | Values |
|------|------|--------|
| **Urgency Level** | Enum | `LOW`, `MEDIUM`, `HIGH`, `EMERGENCY` |
| **Specialist Type** | Enum | `GP`, `CARDIOLOGIST`, `DERMATOLOGIST`, `NEUROLOGIST`, `ORTHOPEDIST`, `GASTROENTEROLOGIST`, `PULMONOLOGIST`, `PSYCHIATRIST` |
| **Symptom** | Value Object | String with validation (3-100 chars, alphanumeric + spaces) |
| **Triage Status** | Enum | `pending`, `processing`, `completed`, `failed` |

### Synthetic Data Rules

1. **All patient data is SYNTHETIC** — generated by AI, tagged with `isSynthetic: true`
2. **Never use real medical records** — even as test fixtures
3. **Synthetic patients have fake demographics** — ages 18-85, randomized genders
4. **Symptoms span all specialist types** — AI varies domains for rich demo data
5. **Urgency distribution varies** — realistic spread (not all EMERGENCY)

### AI Prompt Engineering

**System Prompt Template (Triage Analysis):**
```
You are a medical triage assistant for a DEMONSTRATION system.

Analyze the patient's reported symptoms and context to provide:
1. The most appropriate medical specialist
2. An urgency level based on symptom severity
3. A brief medical justification (2-3 sentences)

Available specialists: GP, CARDIOLOGIST, DERMATOLOGIST, NEUROLOGIST,
  ORTHOPEDIST, GASTROENTEROLOGIST, PULMONOLOGIST, PSYCHIATRIST

Urgency levels:
  - LOW: Non-urgent, routine care appropriate within weeks
  - MEDIUM: Should see specialist within days
  - HIGH: Requires prompt attention within 24 hours
  - EMERGENCY: Immediate medical attention required

CRITICAL RULES:
- This is a DEMONSTRATION. Never provide actual medical advice.
- Respond ONLY with valid JSON matching the schema.
- All analysis is synthetic — do not reference real medical guidelines.
- If symptoms are ambiguous, default to GP with MEDIUM urgency.
```

**System Prompt Template (Synthetic Case Generator):**
```
You are a synthetic medical data generator for a DEMONSTRATION system.

Generate a realistic but FICTIONAL patient case with:
1. Patient age (18-85)
2. Patient gender
3. A set of 2-4 related symptoms (from various medical domains)
4. A plausible medical context (no real patient data)

Vary the medical domains across calls: cardiology, dermatology,
neurology, orthopedics, gastroenterology, pulmonology, psychiatry.

CRITICAL: All data is SYNTHETIC. Do not use real patient records.
Respond with valid JSON: {"age": int, "gender": "male"|"female", "symptoms": [...], "context": "..."}
```

### Output Parsing Rules

```php
// Always validate AI output against expected schema
$validSpecialists = SpecialistType::cases();
$validUrgencies = UrgencyLevel::cases();

if (!in_array($result['specialist'], array_column($validSpecialists, 'value'))) {
    throw new InvalidAiResponseException("Unknown specialist: {$result['specialist']}");
}

if (!in_array($result['urgency'], array_column($validUrgencies, 'value'))) {
    throw new InvalidAiResponseException("Unknown urgency: {$result['urgency']}");
}
```

## Architecture Constraints

1. **AI calls are ALWAYS async** — dispatched through Symfony Messenger
2. **Triage pipeline is a CQRS flow** — SubmitTriageCommand → Handler → AI analysis → TriageCompletedEvent
3. **Frontend polls for results** — TanStack Query `refetchInterval` while status is `processing`
4. **Synthetic cases are scheduled** — Symfony Scheduler, every 60 seconds, can be disabled via env
5. **Admin overrides are allowed** — admin can manually change triage result (for demo purposes)

## Do's and Don'ts

### ✅ Do
- Tag ALL data as synthetic (`isSynthetic: true`)
- Validate AI output against enums before storing
- Use async processing for AI calls
- Provide fallback on AI failure (default to `GP / MEDIUM`)
- Log AI raw responses for debugging (`aiRawResponse` field)
- Use `deepseek-reasoner` for complex cases, `deepseek-chat` for standard

### ❌ Don't
- Store real patient data — ever
- Make blocking AI calls in HTTP request lifecycle
- Skip validation of AI output
- Hard-code medical knowledge in code (goes in system prompt)
- Use real medical guidelines in prompts
- Expose raw AI responses to frontend without transformation
